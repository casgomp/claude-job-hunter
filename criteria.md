## Location

### Fully Remote
- No location restriction — include regardless of where the company is based

### Hybrid
- **Berlin:** always include
- **Within ~2 hours by train from Berlin:** include but flag for manual review — acceptability depends on days onsite per week (fewer days = more acceptable). Cities in scope: Hamburg, Wolfsburg, Hannover, Leipzig, Dresden, Rostock, Potsdam, Brandenburg
- **Outside the ~2h radius:** exclude
- If days-per-week onsite is not specified, flag for manual review rather than auto-excluding

### Fully Onsite
- **Berlin only** — include
- **Anywhere else:** exclude

### General Rule
Hybrid roles are acceptable within ~2 hours by train from Berlin. Fully onsite roles must be in Berlin only.

## Eligibility Filters

### Language Requirements
- **Exclude** roles where C1/C2 German is listed as mandatory with no flexibility
- English-only or mixed English/German environments are preferred
- Roles specifying "German B2+" should be flagged but assessed case by case

### Werkstudent Positions
- **Include** but **flag eligibility risk**: 42 Berlin is not a government-recognized institution, which may disqualify from Werkstudent status at some employers
- Score these lower (Tier 2 by default) and always add an eligibility note

### Degree Requirements
- **Do not exclude automatically** — flag the requirement and assess case by case
- Many tech companies in Berlin waive formal degree requirements for demonstrable skills

---

## Scoring Tiers

### Tier 1 — Strong Match
- Role type: junior / entry-level / intern
- Focus: backend, systems, automation, DevOps, or infrastructure
- Stack: C/C++ explicitly valued, or open/flexible stack
- Language environment: English or mixed English/German
- No hard degree requirement (or degree requirement is soft/waivable)

### Tier 2 — Possible Match
- Frontend-heavy or mixed frontend/backend roles
- Stack is not in current skills but is learnable and not listed as a strict requirement
- Werkstudent roles (flag eligibility risk)
- Roles where German B2 is listed but not described as strictly mandatory
- Roles with soft degree requirements

### Tier 3 — Stretch / Unlikely
- Roles with a recognized degree as a hard requirement
- Heavy mandatory German (C1/C2) with no English option
- Stack very far from current skills AND listed as a strict requirement
- Do not exclude these entirely — surface them so the candidate can decide

## Industry / Domain Preferences

### Relevant Domain Overlap (software engineering roles only)
The candidate's architecture and urban planning background is a **bonus only when the role is a software engineering position** in one of these domains:
- Smart city technology (backend/systems roles)
- GIS or geospatial software development
- Construction tech / PropTech (engineering roles)
- Spatial data pipelines or urban simulation software
- Infrastructure or civil engineering software tools

**Important:** Ignore non-engineering roles in these sectors (e.g., urban consultant, city planner, architecture firm). Domain relevance applies only when the primary job function is software development.

### No Strong Industry Exclusions
- Cast a wide net — do not filter out industries unless there is a specific reason (e.g., role requires credentials outside software)

---

## Things to Avoid
- Roles requiring professional experience (2+ years) as a hard filter
- Exclusively senior/lead/staff positions
- Roles where C1/C2 German is a strict, non-negotiable requirement
- Non-engineering roles in architecture, urban planning, or construction (these are not a career pivot target)
